# Контекст монорепы до интервью

## Входы
`run.feature_request` явно включён в instruction, project workspace, существующие AGENTS/README/docs, доступные тесты.
## Шаги
1. Проверить чтение корня и `git status`; зафиксировать HEAD (или greenfield без первого commit), незакоммиченные изменения.
   Не потерять чужие правки. Недоступный checkout — blocked, а не greenfield.
2. Определить greenfield только по проверяемому отсутствию приложения/действующей продуктовой спецификации.
   Наличие скелета без продукта отметить scaffold; решение об исходном режиме объяснить.
3. Создать уникальный change_id `CHG-<slug>-<6hex>` один раз и сохранить в project `change.json`.
   На повторе использовать тот же ID из переданного индекса/step, не создавать второй CHG.
4. Инвентаризировать модули: входы приложения, API, хранилища, фоновые процессы, shared packages, сборка, тесты,
   legacy docs, критические зависимости. Всё — относительные пути одного Git-корня; никаких репозиторных manifest/clone.
5. Найти релевантные BR/ADR/SRS/тесты; зафиксировать расхождение docs/code как conflict, не молча выбирать удобную версию.
6. Сохранить запрос без технической интерпретации в intent.md, источники и ограничения в context.md.
   Подготовить run `change-index.md` с точными project-путями, change_id, mode, base_commit, кратким impact и неизвестным.
## Формат результата
`templates/context.md`, `templates/change.json`; step-summary дополнить `change_id`, `mode`, `base_commit`.
Рабочие выписки — run `research-notes.md`, НЕ отдельная постоянная база требований.
## Exit criteria
Корень доступен; режим обоснован; ID закреплён; есть ссылки path:locator для material facts; неизвестное видно.
Не задавать ВП технические вопросы, на которые можно ответить чтением монорепы. Код пока не писать.

## Общие ограничения
Работать только внутри текущей HG SDLC-ноды и одной монорепы. Общие правила — в подключённом `hg-pdlc-method@3.0`.
Шаблоны читать относительно фактически материализованного `SKILL.md`, а не из выдуманного пути каталога.
Не доступны обязательный ресурс или сабагент — зафиксировать блокер; не изображать вызов или проверку.
Не менять согласованный upstream: сообщить finding и вернуть работу соответствующему владельцу артефакта.
Полезные результаты — `scope: project`; промежуточные материалы — `scope: run`. Пути брать из контракта ноды.
Записать все declared artifacts и step-summary; один текст «готово» не является результатом.
