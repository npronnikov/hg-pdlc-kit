# Реализация по согласованному контракту

## Входы
Утверждённый PRD, проверенная архитектура/SRS, test-model как read-only oracle, implementation-plan, review/command feedback.
## Шаги
1. Проверить tasks DAG и согласованные source paths. Прочитать приложенный rework: при keep_changes=true
   исправить указанные finding, при false выполнить план на восстановленной базе с теми же BR/SR.
2. Делегировать implementer ограниченный набор файлов/задач; не разрешать двум агентам писать один файл одновременно.
   Родитель консолидирует изменения, проверяет code standards существующей монорепы и task coverage.
3. Реализовать схемы/миграции, доменную логику, границы API/UI и errors/auth; добавить unit/integration tests где нужны.
   Не менять test-model/SRS для того, чтобы принять текущий код. При конфликте — записать причину для review route.
4. Запускать локальные конечные проверки по пути, но окончательный build исполняет следующий command-узел.
   Для зелёного command нужны реальные exit/logs, не пересказ успешной сессии.
5. Сформировать implementation.json: задачи, выполненные SR, точные изменённые файлы, вид изменения, содержательные проверки,
   известные ограничения. Сравнить с git diff, не пропускать новые файлы. Нельзя объявить реализацию без application delta.
## Выходы
project код/миграции/unit tests и docs/changes/<CHG>/implementation.md, implementation.json;
run implementation-index.md. Декларировать ожидаемые изменения по поддерживаемым папкам монорепы.
E2E автоматизирует следующая роль после code review. Не делать push/merge/deploy.

## Общие ограничения
Работать только внутри текущей HG SDLC-ноды и одной монорепы. Общие правила — в подключённом `hg-pdlc-method@3.0`.
Шаблоны читать относительно фактически материализованного `SKILL.md`, а не из выдуманного пути каталога.
Не доступны обязательный ресурс или сабагент — зафиксировать блокер; не изображать вызов или проверку.
Не менять согласованный upstream: сообщить finding и вернуть работу соответствующему владельцу артефакта.
Полезные результаты — `scope: project`; промежуточные материалы — `scope: run`. Пути брать из контракта ноды.
Записать все declared artifacts и step-summary; один текст «готово» не является результатом.
