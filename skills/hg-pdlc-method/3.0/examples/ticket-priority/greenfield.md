# Greenfield — те же flow и форматы
Начало: доступный пустой Git-корень. Фича ВП дополнительно определяет, что такое Ticket и кто его владелец.
ai-context фиксирует greenfield; ai-baseline пишет proposed foundation и N/A AS-IS.
Интервью уточняет создание заявки/идентификацию/публичные границы, не делает вид, что GET и owner уже существуют.
PRD включает минимальный вертикальный срез для создания/чтения и изменения, либо явную разрешённую тестовую подготовку
существования заявки; эти варианты нельзя незаметно смешивать. Architecture выбирает стек по ограничениям ВП.
SRS задаёт API и данные заново, test-model использует новую схему. TASK scaffold предшествует feature TASK.
E2E legacy migration в такой задаче N/A с причиной; вместо него — E2E первого запуска на пустой БД и создания заявки.
В результате та же структура project docs/code/test/evidence, но без восстановленных «наблюдаемых» требований и фиктивной миграции.
Этот файл — пример постановки/маршрута, не отчёт о выполнении отдельной greenfield реализации.
