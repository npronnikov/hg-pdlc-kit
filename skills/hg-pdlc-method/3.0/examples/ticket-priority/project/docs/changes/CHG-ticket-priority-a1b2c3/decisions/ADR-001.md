# ADR-001: Оптимистическая версия для изменения приоритета
Status: accepted in DEMO fixture.
## Context
BR-004/AC-007 запрещают потерю конкурирующего изменения; есть SQLite и краткие транзакции.
## Options
1. Last-write-wins: проще, нарушает BR-004.
2. Проверка version в условии UPDATE: поддерживает конфликт без долгих блокировок.
3. Серверная блокировка с пользовательским lock-token: сложнее, unnecessary для этого scope.
## Decision
Вариант 2. WHERE id/owner/version, version=version+1; stale → 409.
## Consequences
Клиент обязан читать version и обрабатывать 409. Retry без reread не гарантирует успех.
## Invariants / Verification
Ровно один успешный update из двух с expectedVersion=1; E2E-007.
