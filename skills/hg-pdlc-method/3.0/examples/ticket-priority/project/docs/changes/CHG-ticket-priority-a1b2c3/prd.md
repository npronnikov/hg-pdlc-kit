# PRD — Приоритет собственной заявки
Change: CHG-ticket-priority-a1b2c3; revision DEMO-PRD-1; approval — демонстрационная fixture, не событие живого HG.

## 1. Проблема
Владелец не может обозначить срочность отдельной заявки через Ticket API. Количественные данные исследования отсутствуют.
## 2. Цель и гипотеза эффекта
Цель delivery — изменяемый, сохраняемый приоритет с безопасной конкуренцией. Гипотеза продукта: владельцы используют high
для срочных заявок. Возможная будущая метрика — доля активных владельцев, изменивших приоритет за 7 дней; baseline/target unknown.
Событие после будущего выпуска — priority_changed без текста заявки; численного эффекта в этом flow не измеряем.
## 3. Пользователи
Владелец заявки. Другой владелец и неавторизованный клиент не получают доступ. Администраторский override вне scope.
## 4. Границы
In: PATCH приоритета, GET результата, хранение, role isolation, input validation, optimistic conflict, legacy migration.
Out: UI/сортировка/bulk/notifications/administrator override/automated retries/release/outcome analysis.
GET id/title сохраняются; priority/version — аддитивные поля. Клиенты должны игнорировать неизвестные поля.
## 5. Бизнес-сценарии
Владелец читает текущую version, отправляет priority, видит сохранённое состояние. При 409 повторно читает заявку и решает заново;
автоматический повтор без чтения не обещан. Удаления, rollback внешних систем и массовые операции не выполняются.
## 6. Бизнес-требования
| ID | Обязательство | Приёмка |
|---|---|---|
| BR-001 | Владелец может задать low/normal/high для своей заявки; результат сохраняется. | AC-001, AC-002 |
| BR-002 | Неавторизованный пользователь и другой владелец не получают доступ к изменению или содержимому заявки. | AC-003, AC-004, AC-009 |
| BR-003 | Некорректный запрос не меняет заявку и возвращает объяснимую ошибку. | AC-005, AC-006 |
| BR-004 | Конкурирующая запись со старой версией не перезаписывает победившее изменение. | AC-007 |
| BR-005 | Существующие заявки и потребители id/title сохраняют совместимость; default приоритета normal. | AC-008 |
## 7. Правила
Enum low/normal/high; default normal. expectedVersion — положительное безопасное целое. Некорректное поле не меняет state.
При обновлении version увеличивается ровно на 1. Вход — JSON, максимум 8192 байт; payload errors 400, media type 415, oversized 413.
Владелец определяется существующей аутентификацией; нельзя передавать owner для присвоения чужой заявки.
## 8. Критерии приёмки
| ID | Given / When / Then |
|---|---|
| AC-001 | Заявка t-alice принадлежит alice, version=1; когда alice меняет priority на high; тогда 200; priority=high/version=2; последующий GET возвращает то же |
| AC-002 | priority собственной заявки успешно изменён; когда сервис перезапускается на той же БД; тогда GET возвращает сохранённые priority и version |
| AC-003 | Заявка принадлежит другому пользователю; когда bob выполняет GET/PATCH t-alice; тогда 404/not_found, тело заявки не раскрыто, данные не изменены |
| AC-004 | Нет действительного token; когда клиент выполняет PATCH; тогда 401/unauthorized и отсутствие изменения данных |
| AC-005 | Валидный владелец и версия; когда PATCH с priority=urgent; тогда 400/invalid_priority, прежние priority/version сохранены |
| AC-006 | Валидный владелец; когда PATCH с broken JSON, missing/noninteger version либо неизвестным полем; тогда 400 с error для структуры/JSON, 415 для не-JSON content-type, 413 для тела >8192 bytes; состояние заявки не меняется |
| AC-007 | Два клиента прочитали version=1; когда одновременно отправляют разные приоритеты с expectedVersion=1; тогда Ровно один 200 и один 409; версия становится 2, победившее значение не потеряно |
| AC-008 | Существующая таблица без priority/version; когда запускается обновлённое приложение; тогда id/title сохранены; GET содержит priority=normal, version=1 |
| AC-009 | Запрошен отсутствующий id; когда авторизованный пользователь меняет приоритет; тогда 404/not_found как для чужой заявки; существующие записи не изменены |
## 9. Матрица применимости
Роли/запреты: AC-003/004/009. Валидация/границы: AC-005/006. Конкуренция: AC-007. Данные/миграция: AC-002/008.
Время/часовые пояса: N/A, бизнес-операция не зависит от календаря. Retention: изменение не добавляет новый класс данных;
существующая политика продукта не меняется (в учебном примере production policy не задана).
Новая PII: нет, priority — enum; owner существующий. Идемпотентность retry: stale update → 409; retry orchestration вне scope.
Доступность UI: N/A, API-only. Производительность SLA: не устанавливается без продукта/нагрузки; не заявляется проверенной.
## 10. Риски и неизвестное
Production auth и данные эксплуатации отсутствуют; это ограничение учебного продукта, не предположение об их безопасности.
Additive migration требует резервной копии в реальном brownfield; production deployment не выполняется.
