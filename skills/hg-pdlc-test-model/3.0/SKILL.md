# Модель E2E до реализации

## Входы
business.json, system.json, архитектурные границы, существующие регрессионные сценарии, тестовая среда.
## Шаги
1. Для каждого AC сформулировать хотя бы один E2E со входом через публичную границу продукта,
   наблюдаемым результатом, проверкой сохранения/побочных эффектов и отрицательными утверждениями.
2. Описать persona/role, предусловия, данные и очистку, цепочку реальных компонентов, Given/When/Then,
   measurable oracle, timeout, independent isolation и конкретные AC/SR. Никакого UI/API mocking для core цепи.
3. Browser E2E обязателен для UI-фич: браузер → настоящий frontend → backend → настоящее тестовое хранилище.
   Для API-only продукта допустим E2E внешний HTTP-клиент → реальный сервис → БД; это не handler unit-test.
4. Покрыть happy, запреты, некорректные данные, границы, ошибки/повторы/конкуренцию/совместимость по применимости.
   Внешние сторонние sandbox/симуляторы указать на границе; их использование не должно скрывать core behavior.
5. Создать regression selection с причинами. Отдельно перечислить NFR static/integration/performance проверки.
6. В `test-model.json` хранить scenario id, acceptance_ids, system_ids, kind, priority, required,
   chain, data_setup, steps, oracle, cleanup, test_file. Gherkin содержит те же ID в tags.
## Выходы
project test-model.md, test-model.json, scenarios.feature; run test-model-index.md.
Нет автотестов реализации на этом шаге. Они будут написаны после кода по этому oracle, а не наоборот.
При баге реализации запрещено ослаблять oracle/skip; изменение ожидания требует возврата SRS/PRD.

## Общие ограничения
Работать только внутри текущей HG SDLC-ноды и одной монорепы. Общие правила — в подключённом `hg-pdlc-method@3.0`.
Шаблоны читать относительно фактически материализованного `SKILL.md`, а не из выдуманного пути каталога.
Не доступны обязательный ресурс или сабагент — зафиксировать блокер; не изображать вызов или проверку.
Не менять согласованный upstream: сообщить finding и вернуть работу соответствующему владельцу артефакта.
Полезные результаты — `scope: project`; промежуточные материалы — `scope: run`. Пути брать из контракта ноды.
Записать все declared artifacts и step-summary; один текст «готово» не является результатом.
