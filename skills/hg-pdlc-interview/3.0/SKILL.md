# Пакетное интервью ВП после анализа

## Входы
context.md, baseline, существующие product-specs, исходная фича, точные замечания при rework.
## Шаги
1. Сначала составить карту «известно / источник / требует решения». Технические факты не перекладывать на ВП.
2. Сформулировать обычно 3–8 вопросов: пользователь/проблема, in/out, бизнес-правила, негативные сценарии,
   авторизация/конфиденциальность, миграционная совместимость и критерии результата. Это ориентир, не лимит полноты.
3. Для каждого ответа показать реальное последствие выбора. Рекомендация помечается явно, `value` остаётся null.
   Не считать незаполненное required поле согласием с рекомендованным вариантом.
4. Использовать только формат референса `kind: human-form`, `version: "1"`, `fields` c radio/select/checkbox/textarea,
   id snake_case, required, options и value. Не вводить несовместимый собственный UI-контракт.
5. На повторном интервью сохранить уже полученные ответы, если вопрос и основание не изменились;
   спросить только новые/конфликтующие решения. Существенный unanswered вопрос блокирует PRD-review.
## Результат
run `questions.form.json` по `templates/questions.form.json`, run `interview-brief.md` с контекстом и источниками.
Человек редактирует только форму (run/by_ref); в project переносится осмысленный decisions.md на шаге PRD.
## Ограничения
В отличие от generic generate-form-questions из референса, анализ репозитория ОБЯЗАТЕЛЕН до этого шага,
потому что целевая задача — полный brownfield/greenfield процесс, а не smoke формы. Не писать приложение.

## Общие ограничения
Работать только внутри текущей HG SDLC-ноды и одной монорепы. Общие правила — в подключённом `hg-pdlc-method@3.0`.
Шаблоны читать относительно фактически материализованного `SKILL.md`, а не из выдуманного пути каталога.
Не доступны обязательный ресурс или сабагент — зафиксировать блокер; не изображать вызов или проверку.
Не менять согласованный upstream: сообщить finding и вернуть работу соответствующему владельцу артефакта.
Полезные результаты — `scope: project`; промежуточные материалы — `scope: run`. Пути брать из контракта ноды.
Записать все declared artifacts и step-summary; один текст «готово» не является результатом.
